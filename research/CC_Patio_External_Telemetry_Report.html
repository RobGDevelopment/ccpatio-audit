Executive verdict

The origin architecture is critically unstable. NitroPack cache HITs (~107–145 ms) mask baseline browse performance while Cloudflare remains cf-cache-status: DYNAMIC (proxy, not HTML cache). Under forced MISS conditions—even with a four-second pause between single requests—the Brooklyn Corner Sofa PDP recorded a 20,451.7 ms (20.5 second) Time to First Byte stall. That latency class is what produces intermittent Cloudflare HTTP 522 timeouts when the edge stops waiting. Feature freeze and OPcache expansion are mandatory before enabling live WooCommerce sessions or checkout.

2. Scope & objectives

This report documents externally observed behavior of the live production origin serving www.ccpatio.com. The program goal was to determine whether apparent storefront speed is produced by healthy origin compute or by optimizer cache hits—and whether the origin can sustain uncacheable traffic without stalling.

Prior Site Health diagnostics (captured 2026-09-18T12:45:48Z) established that PHP OPcache was 100% full with the interned-strings buffer exhausted (~24 bytes free) on LiteSpeed / PHP 8.2.33 LSAPI. This telemetry campaign tests that diagnosis from outside the firewall, without SSH, LiteSpeed panel, or Cloudflare dashboard access.

In scope

  • HTTP header routing (Cloudflare / NitroPack)
  • TTFB on HIT vs forced MISS paths
  • Heavy PDP / collection page behavior
  • Disabled commerce route cost (cart / checkout / account)
  • Sequential endurance drift on one PDP

Out of scope

  • Concurrent / multi-threaded load testing
  • Payment gateway or checkout conversion UX
  • Visual redesign or merchandising changes
  • Direct OPcache ini edits (requires host access)

5. Finding — Edge masking (NitroPack HIT)

When NitroPack returns x-nitro-cache: HIT, first-byte latency is excellent and can create a false impression of origin health.

URLNitroTTFBHTML sizeCF status
/product/brooklyn-corner-sofa/ HIT 145.3 ms ~3.31 MB DYNAMIC
/collections/bravada-collections/ HIT 106.9 ms ~2.95 MB DYNAMIC
Featured project page (HIT) HIT 135.9 ms ~2.86 MB DYNAMIC

Conclusion: Stakeholder reports that “the site feels fast” align with the HIT path. They do not certify LiteSpeed / PHP worker health under MISS, purge, cron, or session traffic.

6. Finding — Cloudflare DYNAMIC reality

Across baseline, PDP/collection, and endurance runs, Cloudflare consistently presented:

  • server: cloudflare
  • cf-ray present (PHX / LAX)
  • cf-cache-status: DYNAMIC on measured HTML documents

NitroPack—not Cloudflare—owned HTML HIT/MISS transitions (x-nitro-cache, x-nitro-cache-from, x-nitro-rev, and related headers).

Architectural reading On this sample, Cloudflare is operating as an edge proxy / WAF front door. It is not serving HTML page-cache HITs for these URLs. Dual-stack “memory savings” cannot be attributed to Cloudflare HTML caching based on these headers.

Why Attempt 3 matters

A late HTTP 200 after 20.5 seconds is a near-miss timeout, not a healthy response. Cloudflare 522 is emitted when the edge abandons an origin that fails to answer in time. This stall under one sequential client—with a four-second pause after prior requests—shows the origin can lock up without any synthetic flood. Combined with the Site Health finding of a full PHP OPcache, the mechanism is consistent with LiteSpeed / LSAPI workers blocked on opcode eviction and recompile while regenerating a multi-megabyte Elementor PDP.

8. Finding — DOM / payload bloat

The Brooklyn Corner Sofa PDP HTML payload was approximately 3.3 MB on the HIT path. Plugin footprints observed in markup included Elementor, Elementor Pro, WooCommerce, Variation Swatches, Astra Addon, Favorites, and EMCP Pro (non-exhaustive; not all of the 38 active plugins enqueue assets on every URL).

Each forced MISS must rebuild that document through the full WordPress / builder / commerce bootstrap. Large payloads amplify CPU time, transfer time, and OPcache working-set pressure.

9. Finding — Soft-404 commerce tax

Transactional routes are effectively disabled (catalog-oriented posture; YITH Catalog Mode present in the DOM). Despite that, disabled commerce URLs still incurred full storefront boots:

PathStatusBody sizeTTFB bandNitro
/cart/ 404 ~2.2–2.3 MB ~480–560 ms MISS / disabled
/checkout/ 404 ~2.2–2.3 MB ~480–560 ms MISS / disabled
/my-account/ 404 ~2.2–2.3 MB ~480–560 ms MISS / disabled

Conclusion: Turning checkout “off” does not remove origin cost. Bots and broken links still force multi-megabyte WordPress boots. Enabling real sessions later adds additional uncacheable load on top of an already fragile MISS path.

10. Agency claim assessment

PrimeView asserted that Cloudflare and NitroPack “work together” via API integration and that NitroPack “packs to use less memory,” implying the dual stack is non-conflicting and memory-helpful.

Claim themeTelemetry reading
Both systems jointly cache HTML to save memory CF remained DYNAMIC; Nitro owned HIT/MISS. Not dual HTML HIT caching on this sample.
“Packing” reduces server memory pressure Packing reduces payload bytes. OPcache / PHP worker RAM is a separate ledger. MISS path still stalled for 20.5s.
API integration prevents conflict Purge coordination (if present) does not stop origin PHP on MISS, does not expand OPcache, and did not prevent the stall.

11. Limits of this study

  • External probes cannot print live opcache* percentages; Site Health remains the direct OPcache measurement.
  • These runs did not capture a Cloudflare 522 error page; they captured a 20.5s near-timeout stall (stronger mechanistic proof for this window).
  • Multi-server load-balancer topology remains an unverified agency statement.
  • Results reflect PHX-adjacent probing at the stated UTC times; absolute TTFB varies by network path.

12. Mandatory gates & remediation

No go-live of transactional WooCommerce sessions/checkouts until the following gates are met.

P0 Host / SysAdmin Expand OPcache memory and interned-strings buffer; verify not full Site Health: opcode_cache_full=false; hit rate ≥ 90%

P0 PrimeView Declare single HTML cache owner (NitroPack or Cloudflare) Signed architecture note; CF rules match choice

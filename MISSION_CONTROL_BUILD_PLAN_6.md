## 1. Shared invariants

Every packet below inherits these. A packet QCA that passes typecheck, lint, and the target test is still `DEFECT_REJECTED` when an auditor finds one of these in the diff.

1. **Lock before code.** `phase_id` is the packet id. `expected_blast_radius` equals the allowed-file count in that packet. `base_ref` is `HEAD`. `override_blast_cap` is false.
2. **Diff equals the lock.** The working diff against `HEAD` contains exactly those files. `.cursor/aar.json` is generated by the audit and is excluded from the count. `.cursor/session-stamp.json` and `.cursor/logs/qca-last.log` are never part of the diff. Drop them with `git restore` before the audit. Do not commit, then audit.
3. **Role gate stays server-side.** `SuperAdmin` and `IT_Admin` may enter. `Ops_Manager`, `Designer`, a missing `user_roles` row, and `ghl-embed@ccpatio.com` may not. The page, the proxy, and every server action agree. A client prop is not a role.
4. **Unframeable.** `/mission-control` does not join the GHL `frame-ancestors` list and does not accept `?embedKey=`.
5. **Read the hub. Do not drive it.** No V8 bus, no Woo order webhook, no `syncGhlOpportunity`, no `POST /manufacturing_orders`, no make-to-order, no `product_bom_draft` insert, no `sync_to_woo` or `sync_to_clover` update, no new `channel_sync.channel`.
6. **Secrets stay off the wire and out of the log.** Responses, inbox copy, and traffic-light detail strings never contain a vendor token, a refresh token, or an `Authorization` header. `console` and `pim_audit_log` do not store the key.
7. **Money format.** Any new currency display uses `.toFixed(2)` only.
8. **Certification.** `npm run typecheck`, `npm run lint`, and the packet `target_test` pass inside `qca.mjs`. Exit 2 is not renamed.

| Target test | `npx vitest run tests/mission-control-rbac.test.ts` |
| Blast | 6 |

Allowed files:

- `.cursor/phase.lock`
- `src/server/mission-control/require-role.ts` — create. Input is the auth user id. Read `user_roles` through Drizzle on `POSTGRES_URL`. Return the role only for `SuperAdmin` and `IT_Admin`. Otherwise throw a structured unauthorized error. No embed-key branch.
- `src/proxy.ts` — `/mission-control` keeps using that same allow-list. Do not add the path to `isGhlFrameablePath`. Do not let the e2e god-mode cookie grant Mission Control unless the test file is the only caller and the cookie is already the harness secret.

## 3. Packet `mc-6b-vault-caching`

Rotate a key, drop the cache, and stop the browser from ever seeing the stored value again.

| | |
|---|---|
| Intent | `KeyManager` tests one vendor with a single `limit=1` probe, then `saveVendorKeyAction` upserts `vendor_credentials` and calls `invalidateVendorKey`. The following read comes from Postgres, then the 5-minute LRU. The client receives ok or a status code, never the stored token. |
| Target test | `npx vitest run tests/vendor-vault.test.ts` |
| Blast | 5 |

Allowed files:

- `.cursor/phase.lock`
- `src/utils/vault.ts` — keep max 50 and TTL 5 minutes. `getDecryptedVendorKey` remains the only reader. Do not add pgsodium. Do not log the token.
- `src/app/mission-control/actions.ts` — `testVendorKeyAction` and `saveVendorKeyAction` stay behind `requireMissionControlAuth`. Test is one GET per click for `katana`, `woocommerce`, or `clover`. Save writes `encrypted_token`, sets `updated_by`, and invalidates that service only.
- `src/components/mission-control/KeyManager.tsx` — the field is write-only. After save it clears. Errors show the HTTP status, not the response body.
- `tests/vendor-vault.test.ts` — create. Cache hit skips a second query. `invalidateVendorKey` forces the next read. A saved value is absent from the action's return object.

QCA invariants:

- No pgsodium migration, no new secrets table, and no claim that `encrypted_token` is encrypted. The financial blueprint already recorded that it is plaintext.
- The action return and the component state never hold the value read back from `vendor_credentials`.
- A test click does not call `syncBOMToKatana`, Woo product write, or Clover item write.
- `qbo_auth_tokens` is out of scope. QuickBooks refresh stays on its existing lock.

| | |

| Target test | `npx vitest run tests/mission-control-traffic.test.ts` |
| Blast | 5 |

Allowed files:

- `.cursor/phase.lock`
- `src/server/mission-control/sync-matrix.ts` — create. Count `channel_sync` grouped by `channel` and `status` for `katana`, `woocommerce`, and `clover`. Derive the lamp from those counts plus the existing `SpokePingResult`. Pure function, no HTTP.
- `src/app/mission-control/health-action.ts` — still calls `requireMissionControlAuth` and `runSpokeTokenHealthCheck`. Attach the matrix. Do not pass `silent` through to a writer.

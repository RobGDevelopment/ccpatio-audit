2. Purpose & scope

This audit evaluates architectural and operational stability of the WordPress infrastructure operated for CC Patio and built/maintained by PrimeView. Staging has been reported as fragile (PHP 8.2, intermittent Cloudflare 522s, heavy plugin load including NitroPack, Elementor, and Spectra).

In scope: runtime environment, caching topology, plugin overlaps, request path, and a concrete remediation punch list.
Out of scope: visual redesign, VividWorks configurator feature work, and catalog merchandising — all deferred until the stability gate in §8 is met.

3. Priority findings

OPcache saturated — primary 522 driver Critical
Opcode cache is FULL. Interned strings at 100% (24 bytes free of 8 MB). Hit rate only 56.64%. Every cold/miss request recompiles PHP under LiteSpeed → origin stalls past Cloudflare’s ~100s handshake timeout → HTTP 522.
PHP 8.2 is past End-of-Life Critical
Runtime is PHP 8.2.33. PHP 8.2 reached EOL November 2025. As of September 2026 there are no security patches. Staging/production should target PHP 8.3 (or 8.4) after a plugin compatibility matrix.
NitroPack + Cloudflare double-proxy stack Critical
WP_CACHE=true, advanced-cache.php drop-in present, NitroPack 1.20.1 active while Cloudflare proxies the edge. Classic purge storms, origin loopbacks for optimization, and competing TTL policies that amplify origin load during cache misses.
38 active plugins + dual builders High
Elementor 4.2.4 + Elementor Pro 4.2.3 alongside Spectra Legacy 2.20.3 and Astra Pro. Two page-builder stacks on every frontend bootstrap. Plugin tree alone is 593 MB on disk.
Broken Link Checker active in production High
BLC 2.4.14.1 continuously crawls and writes to the database. On a ~47 GB media site this is a known origin-CPU / MySQL contention source and should be offline or scheduled off-peak via CLI only.
WP_DEBUG enabled in production High
WP_DEBUG=true with log to /home/ccpatpvlive/logs/ccp-wp-errors.log. Extra logging I/O under load worsens LiteSpeed worker saturation. Keep DEBUG_LOG only if rotated and sampled under incident flag.
Uploads balloon: 43.69 GB Medium
Media library is ~92% of total site footprint (47.42 GB). Imagick is available but upload_max_filesize is only 20 MB — legacy originals likely retained without WebP/AVIF lifecycle or object-storage offload.
Security / header plugin pile-up Medium
Wordfence + Limit Login Attempts + WPS Hide Login + Temporary Login Without Password, plus Header Footer Code Manager AND WP Headers And Footers. Overlapping auth gates and duplicate head/footer injection points.
Dual schema / SEO stacks Medium
Rank Math SEO 1.0.278 plus Schema & Structured Data for WP & AMP 1.66. Competing JSON-LD emitters cause invalid markup and extra frontend work.
Site Kit not connected; environment constants soft Low
Google Site Kit scopes unauthenticated despite a G- measurement ID present. WP_HOME / WP_SITEURL / WP_ENVIRONMENT_TYPE undefined — fragile for CDN URL rewriting and environment parity.

5. Caching & network ingress conflicts

Cloudflare edge

Proxies www.ccpatio.com as WAF + optional HTML cache. On miss, waits for origin; prolonged PHP/DB stall yields HTTP 522. Site Kit reports reference URL https://www.ccpatio.com with Search Console property https://ccpatio.com/ (apex vs www — confirm canonical consistency).

NitroPack origin layer

advanced-cache.php drop-in + WP_CACHE=true. Optimization may trigger origin self-requests (loopbacks) and aggressive purge fan-out when WooCommerce / Elementor content changes. Under plugin churn, purge storms force simultaneous cold PHP boots — worst case for a full OPcache.

Conflict modeSymptomMitigation
Double HTML cache Stale or thrashing pages; purge races One owner: Cloudflare APO/Cache Rules or NitroPack — not both
Optimization loopback Origin CPU spikes; Cloudflare sees slow origin Disable NitroPack remote optimize; warm via Cloudflare
Purge on every SKU edit Catalog updates → mass cold starts Scoped purges; queue; off-peak cron
Cloudflare ~100s origin wait Intermittent 522 under load Fix OPcache + plugin boot; do not only raise timeouts

7. System communication flow

Request path from client through Cloudflare to origin, PHP, plugins, MariaDB, and outbound SaaS. Cloudflare 522 responses occur when the edge (hop 2) waits on hops 3–6.

1. Browser
HTTPS request to www.ccpatio.com (WooCommerce PDP / archive / Elementor page).
2. Cloudflare Edge
Proxy + WAF. If HTML is not cached at edge → origin fetch. Miss/purge → full PHP path. Timeout waiting on origin → HTTP 522.
3. Origin LiteSpeed
TLS terminate; static vs dynamic routing. Hits advanced-cache.php (NitroPack drop-in) before WordPress bootstrap.
4. PHP (LSAPI)
PHP 8.2.33 under LiteSpeed. OPcache FULL → compile thrash. Loads WP core + 38 plugins + Astra + 7 Code Snippets.
5. Application layer
Elementor/Spectra render, WooCommerce queries, Rank Math + Schema JSON-LD, NitroPack optimize/rewrite, Wordfence checks.
6. MariaDB 10.11
518 MB catalog/options/transients. Broken Link Checker + Activity Log + Woo sessions compete for connections (max 151).
7. Outbound APIs
NitroPack SaaS, Gravity Forms Zapier, Podium, Site Kit/GA4, Rank Math, accessiBe, WebToffee feeds — each adds latency on admin or cron paths.

8. Prioritized remediation punch list

Hand this list to PrimeView and hosting before any further feature development. P0 items are stability gates.

PriOwnerActionAcceptance criteria
P0 Host / SysAdmin Resize OPcache: raise memory (≥256–512 MB), interned_strings_buffer (≥16–32 MB), tune revalidate_freq; confirm opcode_cache_full=false and hit rate >90%. Site Health shows OPcache not full; measurable p95 TTFB drop on origin.
P0 PrimeView + Host Resolve CF 522s: raise LiteSpeed workers / PHP LSAPI children; disable NitroPack or Cloudflare HTML cache — pick one; purge both after change. Zero 522s for 72 hours in Cloudflare Analytics; origin responds <5s warm.
P0 PrimeView Deactivate Broken Link Checker immediately; remove from autoload; clear BLC cron hooks. No BLC cron in wp-cron / Action Scheduler; DB write rate drops.
P1 PrimeView Deactivate Spectra Legacy, Schema plugin, Importer, Better Search Replace, Temporary Login (if unused); consolidate header plugins. Active plugin count ≤28; no dual schema in view-source.
P1 Host Plan PHP 8.3 (or 8.4) upgrade on a staging clone first; run WooCommerce / Elementor / cache-plugin compatibility matrix. Staging on supported PHP with green smoke tests.
P1 PrimeView Set WP_DEBUG=false in production; retain rotated DEBUG_LOG only under incident flag; define WP_ENVIRONMENT_TYPE=production and hardcode WP_HOME / WP_SITEURL. Site Health constants match; log growth rate controlled.
P2 PrimeView + Media Media lifecycle: offload/archive cold uploads, regenerate WebP/AVIF, raise upload limits only after CDN offload. Uploads directory trend flat or declining month-over-month.
P2 PrimeView Freeze net-new plugin installs until stability gate passes; document Code Snippets 8–14 as version-controlled mu-plugin candidates. Change-control checklist signed; snippets in repository.
P2 Ops Reconnect or remove Google Site Kit; verify Rank Math Search Console ownership; enable consent mode if accessiBe/CMP required. Analytics auth green or plugin removed.
P3 Agency Staging parity: clone production with same LiteSpeed / PHP / OPcache; load-test product archive + variation PDP before further feature work. Staging survives 50 concurrent PDP loads without 5xx.

9. Stability gate (stop-ship criteria)

No net-new feature development (Elementor templates, Spectra work, VividWorks embeds, large catalog imports, or production PHP major upgrades without staging proof) until the following are true:

Must be true

  • OPcache not full; hit rate ≥ 90%
  • Active plugins ≤ 28 after decommissions
  • Single cache owner (Cloudflare xor NitroPack)
  • Broken Link Checker deactivated; no crawl crons
  • WP_DEBUG false in production
  • 72 hours with zero Cloudflare 522s

Explicitly deferred until gate

  • New Elementor templates / Spectra work
  • VividWorks configurator embeds
  • Large catalog imports / feed regenerations
  • Production PHP major upgrade without staging proof
